## Complaint 1 — you can't see what you're spending until it's spent

The longest-running thread in the official forum: ["Pro Plan Rate Limit Transparency Issues — Need Specific Usage Details"](https://forum.cursor.com/t/pro-plan-rate-limit-transparency-issues-need-specific-usage-details/113028), opened 3 Jul 2025, still running across three pages. The asks: a dashboard showing dollars consumed against the allowance, an exact reset time, worked examples of typical vs. heavy usage. Cursor staff (danperks, 4 Jul 2025) advised switching to Auto for cheaper models and repeated "every few hours" rather than giving a reset time. A parallel thread, ["New Pro Plan — Need More Transparency on Rate Limits"](https://forum.cursor.com/t/new-pro-plan-need-more-transparency-on-rate-limits/105591), runs two pages.

Partly addressed since. [Usage and limits](https://cursor.com/help/models-and-usage/usage-limits) (fetched 17 Sep 2026) says the Spending tab shows "real-time usage for both pools, remaining allowance, and any on-demand charges" plus the reset date; usage resets with the billing cycle and doesn't roll over. The docs still don't publish included usage per tier — only that "higher-tier plans include more usage." The in-product number now exists; the pre-purchase number does not.

Live instance: Auto moved from a flat rate to **per-model pricing on 24 Aug 2026** — the rate of whichever model the request was routed to. Announced by email from `team@mail.cursor.com`, which said "for most requests, this means a higher rate than the current flat rate" and that Cursor-model limits were raised ([explainx recap](https://explainx.ai/blog/cursor-auto-per-model-pricing-usage-limits-august-2026)). **No Cursor blog or changelog post for this change: not found.**

## What competitors already do about these

- **Spend visibility before purchase:** GitHub publishes the dollar value of included credits per tier ($15 Pro / $70 Pro+ / $200 Max) and $0.01 overage ([Copilot plans](https://github.com/features/copilot/plans), fetched 16 Sep 2026 for Wednesday's file; not re-fetched today). Cursor publishes neither.
- **Spend caps:** GitHub [budget controls](https://docs.github.com/en/copilot/tutorials/budgets/getting-started-with-budget-controls) offer user-level budgets, per-user overrides and enterprise spending limits, with "Stop usage when budget limit is reached" converting alerts into a hard stop — off by default. Cursor's docs describe a notification and an upgrade path, not a cap.
- **Claude Code** publishes no per-plan numbers either: `/cost` covers API-key billing only, and enterprise seats get a "limit reached, resets at *time*" message ([Claude help centre](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code), fetched 17 Sep 2026). Opacity isn't unique to Cursor; publishing dollar values is Copilot's position alone of the three.
- **JetBrains:** Copilot ships a supported JetBrains integration ([GitHub Docs](https://docs.github.com/en/copilot/concepts/agents/copilot-in-jetbrains)) — one of Cursor's loudest open requests is table stakes elsewhere. Copilot's Jupyter status: not verified today.
